# Security Policy

We take the security of Sacred Music Fellowship projects and our community's data seriously.

## Reporting a vulnerability

**Please do not report security issues in public issues, discussions or pull requests.**

Report them privately instead:

1. Go to the affected repository's **Security** tab and click **Report a vulnerability** (GitHub private vulnerability reporting).
2. If that isn't available, email **[jane@sacredmusicfellowship.org](mailto:jane@sacredmusicfellowship.org)**.

Please include:

- The repository and the affected area (page, API route, file)
- Steps to reproduce, or a proof of concept
- The impact you think it has (for example, access to other users' data)

## What to expect

- We'll acknowledge your report within **5 business days**.
- We'll keep you updated as we investigate and fix it.
- Once it's fixed, we're happy to credit you unless you'd rather stay anonymous.

We're a small nonprofit team, so please give us reasonable time to fix an issue before disclosing it publicly.

## Supported versions

Only the latest version on the `main` branch of each repository receives security fixes.
