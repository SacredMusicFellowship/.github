# Contributing to Sacred Music Fellowship projects

Thanks for helping! Sacred Music Fellowship (SMF) is a Berkeley-based nonprofit uniting people from diverse cultures and traditions through music. This guide applies to every repository in the [SacredMusicFellowship](https://github.com/SacredMusicFellowship) organization unless a repository has its own `CONTRIBUTING.md`.

## Ways to contribute

- **Report a bug**: open an issue using the bug report template.
- **Suggest an idea**: open an issue using the feature request template.
- **Improve docs**: fixes to READMEs and guides are always welcome.
- **Write code**: pick an issue labeled `good first issue` or `help wanted`, and comment that you're taking it.

For security issues, **don't open a public issue**. Follow [SECURITY.md](SECURITY.md) instead.

## Making a change

1. Fork the repository (or create a branch if you're an org member).
2. Create a branch from `main` with a short, descriptive name, e.g. `fix/jam-search-timezone`.
3. Make your change. Keep each pull request focused on one thing.
4. Run the project's tests and linters locally. The repository README explains how.
5. Open a pull request against `main` and fill in the template.
6. A maintainer will review it. Please respond to feedback, and push follow-up commits rather than force-pushing during review.

## Guidelines

- **Commits**: write clear messages in the imperative mood ("Add jam filter by day").
- **Tests**: add or update tests for any behavior you change.
- **Secrets and data**: never commit API keys, passwords, `.env` files or real user data.
- **Accessibility**: our community spans all ages and abilities, so UI changes should be keyboard- and screen-reader-friendly.

## Code of Conduct

Everyone taking part in SMF projects is expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions

Ask in an issue on the relevant repository, so the answer can help others too. For anything private, email [jane@sacredmusicfellowship.org](mailto:jane@sacredmusicfellowship.org).
